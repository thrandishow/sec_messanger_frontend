# sec_messanger_frontend — Шифр-связь

Русскоязычный интерфейс локального мессенджера: Next.js 16.4.5, React 19,
TypeScript, Lucide. Работает с API и InspIRCd из соседней папки `project_back`.
Никаких внешних шрифтов, CDN, облачных API и аналитики.

## Запустить всё одной командой

Нужен только работающий **Docker с Compose v2**. Папки `project_front` и
`project_back` должны лежать рядом. На Windows используйте Docker Desktop и WSL.

```bash
cd project_front
./start.sh 192.168.1.10
```

Замените `192.168.1.10` на LAN-IP компьютера-сервера. Первый запуск создаёт
сертификаты и секреты внутри Docker и запускает три сервиса: `web`, `api`, `inspircd`.
Node.js и OpenSSL на компьютере для этого не нужны. Первая сборка скачивает
зависимости; затем мессенджер работает без интернета.

1. Установите `../project_back/runtime/tls/ca.crt` как доверенный локальный CA
   на клиентских устройствах. Закрытые ключи `.key` никому не передавайте.
2. Откройте **`https://192.168.1.10:8443`**.
3. На вкладке регистрации задайте ник и пароль (не менее 12 символов), введите
   приглашение от администратора. Код — `REGISTRATION_TOKEN` в серверном `.env`;
   он не встроен в приложение и не выводится скриптом запуска.

Повторный запуск: `./start.sh` — настройки и аккаунты сохраняются.
Остановка и состояние из `project_back`:

```bash
docker compose down
docker compose ps
docker compose logs --tail=100 web api inspircd
```

В Compose только `web` публикует порт `LAN_IP:8443`. Nginx раздаёт результат
`next build` и проксирует `/api/*`, `/health/*`, `/ws` к API, проверяя его TLS-сертификат.
Общая конфигурация — `../project_back/compose.yaml`; повторной настройки URL для UI нет.

## Что умеет интерфейс

- Вход, регистрация по приглашению, восстановление сессии после обновления, выход.
- Вход в комнаты и создание новых по имени, выход из комнаты.
- Личные диалоги по нику или нажатию на участника, счётчик непрочитанных, поиск диалогов.
- Участники комнаты, серверное время сообщений и подтверждение приёма сервером.
- Лимит 350 байт UTF-8 с видимым счётчиком. Неотправленный текст остаётся в поле ввода.
- Автоматическое переподключение с повторным входом в комнаты и ручной повтор после ошибки.
- Явная ошибка при входе в один аккаунт из второй вкладки или с другого устройства.
- Адаптивная навигация для мобильных экранов, клавиатурное управление формами и диалогами.

Ограничения: E2EE, серверной истории, вложений и офлайн-доставки пока нет.
Сервер обрабатывает открытый текст; HTTPS/WSS защищают транспорт. Вкладка хранит
до 200 сообщений на диалог и до 50 диалогов только в памяти. После обновления
или выхода эта переписка исчезает. Галочка у сообщения означает приём IRC-сервером,
а не доставку или прочтение собеседником. Пароли, cookie и приглашения не пишутся
в localStorage; HttpOnly-cookie управляет сервер.

## Разработка без Docker для UI

Нужен Node.js 24, запущенный бэкенд и сертификаты из его setup.
Имя/IP в адресах UI и API должно совпадать: например оба используют `localhost`.

```bash
npm ci
NEXT_PUBLIC_API_URL=https://localhost:8443 NEXT_TELEMETRY_DISABLED=1 npm run dev
```

`npm run dev` запускает Next.js по HTTPS на порту 3000, используя локальные
сертификаты `../project_back/runtime/tls/server.*`. Откройте `https://localhost:3000`.
При готовом Docker Compose можно использовать его HTTPS API на LAN-IP вместо
localhost; в этом случае задайте `NEXT_PUBLIC_API_URL=https://LAN-IP:8443` и
открывайте UI по `https://LAN-IP:3000`. Origin с портом 3000 должен присутствовать
в `ALLOWED_ORIGINS` бэкенда — setup добавляет его.

```bash
NEXT_TELEMETRY_DISABLED=1 npm run check
```

Команда проверяет TypeScript, запускает 6 тестов состояния чата и собирает
статический Next.js frontend в `out/`. В production его обслуживает Nginx;
`next start` для режима `output: 'export'` не используется.

Для проверки всего HTTP/WSS-тракта без Docker есть `npm run test:stack`
в `project_back` (нужны локальные бинарники Nginx и InspIRCd).
Эта проверка и production-сборка прошли. Docker-запуск, визуальная проверка
в браузере и проверка с двух физических устройств в текущей среде не выполнялись.

## Структура

```text
app/                   Next.js App Router, стили, иконка
components/            вход, основной интерфейс, модальные окна
lib/api.ts             HTTP-клиент с cookie
lib/protocol.ts         типы JSON-протокола и локализованные ошибки
lib/chat-state.ts       состояние диалогов и обработка событий
lib/use-chat.ts         WebSocket, сессия, переподключение
test/                  тесты маршрутизации сообщений и состояния
nginx.conf             HTTPS, статика, API и WebSocket proxy
Dockerfile             сборка Next.js → Nginx
start.sh               запуск общего Compose из project_back
```

Контракт бэкенда: `../project_back/docs/api.md`. Типы в `lib/protocol.ts`
соответствуют этому контракту; серверные зависимости и секреты в клиент не импортируются.
